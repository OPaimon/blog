## Overview

Personal blog built with **Lume 3** (Deno-native static site generator). No Node/npm toolchain — everything runs through Deno. Content lives in `src/posts/` as Markdown/MDX. A separate LumeCMS admin panel (`_cms.ts`) is deployed to Deno Deploy for content editing via GitHub.

## Commands

```bash
deno task serve     # dev server with live reload at http://localhost:3000 (front-end at /, CMS admin at /admin)
deno task build     # build static site into _site/
deno task lume      # raw Lume CLI passthrough, e.g. `deno task lume upgrade`
deno lint           # lint (uses the Lume lint plugin configured in deno.json)
deno fmt            # format
```

There is no test suite. Verify changes by building or running the dev server.

## Architecture

**Two entry points, two runtimes:**

- `_config.ts` — the Lume site definition. Builds the static front-end. Applies the plugin chain from `plugins.ts`.
- `_cms.ts` — a standalone LumeCMS instance exported with `.fetch`, run via `deno serve`. It branches on `DENO_DEPLOYMENT_ID`: locally it uses filesystem storage (no credentials needed, served at `/admin`); on Deno Deploy it switches to GitHub storage (writing to `opaimon/blog/src` via `GITHUB_TOKEN`) and serves at root `/`, gated by `CMS_USER`/`CMS_PASSWORD` Basic Auth.

**Dependencies** are URL imports pinned in `deno.json` imports map (Lume + plugins from jsdelivr, UnoCSS from npm). `deno.lock` is committed. There is no `package.json`; `node_modules/` only exists because UnoCSS is an npm import.

**Plugin chain** (`plugins.ts`) — order matters. Key behaviors:
- `mdx` — `.mdx` posts are supported alongside `.md`.
- `slugifyUrls` configured with `alphanumeric: false` to **preserve non-ASCII (CJK) characters** in URLs. Do not "fix" this to ASCII-only.
- `toc` (markdown-plugins) uses a custom `slugify` that keeps CJK (`一-鿿`) for heading anchors. The `toc` variable it exposes is consumed by `post.vto`.
- `feed` generates `/rss.xml` + `/rss.json` from pages matching `url^=/posts/`, newest 20.
- Also: `metas`, `date`, `sitemap`, `robots`, `readingInfo`, `minifyHTML`.

**Content model:**
- `src/posts/_data.yml` sets `type: post` and `layout: layouts/post.vto` for everything in `posts/`. The `type=post` tag is the contract used by every listing query.
- Listing pages query posts with `search.pages("type=post draft!=true", "date=desc")` — front page (`index.vto`), posts index (`posts/index.vto`), and `tags.page.ts`. Drafts (`draft: true`) are excluded everywhere.
- `tags.page.ts` is a generator that yields both the `/tags/` index and one page per tag.
- Post frontmatter: `title`, `author`, `description`, `date`, `updatedDate`, `tags` (list), `draft` (bool). These fields mirror the CMS field definitions in `_cms.ts` — keep the two in sync when changing the content schema.

**Templates** are Vento (`.vto`). `_includes/layouts/base.vto` is the shell (header nav from `_data.yml` `nav_links`, RSS link, footer); `post.vto` extends it with TOC sidebar, prev/next navigation, and tag links.

**Styling** is UnoCSS (`unocss.config.ts`, Wind3 + typography presets, dark mode via `media`). Preflight is intentionally minimal to avoid clobbering existing styles. Hand-written CSS lives in `src/styles/global.css`, which defines the `--site-container-*` custom properties and the scroll-driven header-shrink animation referenced by the `site-header-inner` shortcut. The `style.css` bundle is generated by the UnoCSS plugin.
